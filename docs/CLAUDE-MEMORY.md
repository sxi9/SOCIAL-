## bored-chat-deployment

_Bored Chat (repo sxi9/SOCIAL-, local clone D:\\physical_ai\\SOCIAL) runs on the Ubuntu box in ~/socialchat via docker compose; how to inspect it, local tooling quirks on the Windows laptop_

Bored Chat (formerly SocialChat) is the user's self-hosted chat PWA. GitHub repo is `sxi9/SOCIAL-` (trailing dash; the user types it as SOCIAL), branch main. Local clone: D:\physical_ai\SOCIAL. Production runs on the Ubuntu laptop (saibala@192.168.29.22, see dropzone server) at `~/socialchat` as compose project `socialchat`: caddy publishes 8080 (http) and 9443 (https); api/worker/web/postgres/redis/minio are compose-network only. Public access since 2026-10-18: Tailscale Funnel on port 10000 -> http://127.0.0.1:8080, i.e. https://leakwatch.tail765a4c.ts.net:10000 (stable across reboots; `.env` PUBLIC_ORIGIN is set to it, so OG previews and WebAuthn rpID derive from it). Funnel is internet-reachable ONLY on 443/8443/10000 (the CLI accepts other ports but the ingress never answers). The Caddyfile has a `:80` catch-all site (commit bc6ad3d) because Funnel keeps the public Host header. The old cloudflared quick tunnel (user unit `cloudflared-socialchat.service`, random *.trycloudflare.com hostname per start, which is what killed all shared links on 2026-10-18) was disabled and stopped on 2026-10-18 after the user confirmed the Funnel URL from a phone on mobile data (unit file still exists under ~/.config/systemd/user, re-enable only as an emergency fallback). Renaming the machine (admin console / `tailscale set --hostname`) would change this URL AND every other Funnel link on the node. 2026-10-18: admin panel Users tab can now set a user's password and grant/revoke admin (routes /api/admin/users/:id/password|grant-admin|revoke-admin, commit a3af7b2, ADR-013 amended; CLI stays the only way to revoke yourself). The only admin account is samurai_sastha. CI had been failing at pnpm setup since the packageManager pin; fixed in ffa7be9 (then test fixes b5f75ad + 2a5e222: advisory lock in test/helpers/migrations.ts and vitest fileParallelism:false because suites share one DB; CI green since 2a5e222). Also 2026-10-18 (owner asks): chats open at first unread/bottom with a ResizeObserver pin, composer autofocus only on fine pointers, undo-send pill removed (SPECS standing decision), ALL window.confirm replaced by lib/confirm.ts + ConfirmSheet (GlobalOverlays), DELETE /api/conversations/:id deletes a group (admin) / channel (owner) for everyone. `./bored update` can leave OLD containers running after a build: always follow it with `docker compose up -d --no-build api worker web` and verify with `docker compose exec api grep` for a new string. Anonymous messages: users.anon_messages defaults to 'connections' and the instance had 0 connections, so every anon send was refused by design (404 anon_unavailable), not a bug. VAPID keys are unset (push disabled), TURN_SECRET empty (no relay for calls across NATs). Push to GitHub over SSH (`git@github.com:sxi9/SOCIAL-.git`; the gh HTTPS login saibala2905 has no push rights). Deploy with `./bored update` on the box, then CHECK `docker compose ps`: on 2026-10-18 it rebuilt the web image but left the old web container running ("Up 8 hours"); `docker compose up -d --no-build web` recreated it. Inspect with `ssh saibala@192.168.29.22 'cd ~/socialchat && docker compose logs --since 8h --no-log-prefix api'`; DB via `docker compose exec -T postgres psql -U socialchat -d socialchat` (pipe a .sql file over ssh stdin to avoid quoting pain). The api logs 4xx only as status codes (never the error code); `remotePort` in api logs is Caddy's pooled upstream port, not a client identity.  DEV MODE ON THE BOX IS DANGEROUS: on 2026-10-18 running next dev + tsx watch + tsc --watch there (~/socialchat-dev, scripts in ~/bc-dev: dev.sh / stop.sh / .env.dev pointing at the container bridge IPs 172.18.0.x, ports 3100 web / 3101 api, reached via `ssh -N -L 3100:127.0.0.1:3100`) pushed the already-swapped host into thrashing: SSH banner timeouts and the LIVE app stopped answering for 10+ minutes. Do not start the dev loop there again unless Firefox/leakwatch are closed and >2 GB is free; prefer dev on the laptop (Docker Desktop needs admin) or deploy-only. The host is chronically overloaded (Firefox + ~/leakwatch python eat the CPU, swap full), which made call hang-ups take 10-16 s on 2026-10-18.

Windows laptop tooling: `corepack enable` fails with EPERM (Program Files); use `npm i -g pnpm@10.28.0` and add `$(npm prefix -g)` to PATH in Git Bash. Docker Desktop's `com.docker.service` is stopped and needs admin to start, so server integration tests (need Postgres/Redis, and v1.0a needs MinIO) cannot run locally; CI has Postgres+Redis but no MinIO.

**Why:** the user does local development here and deploys with `./bored update` on the box; knowing the layout avoids re-discovery.

**How to apply:** never run integration tests against the live DB; propose config changes on the box (PUBLIC_ORIGIN, restarts) rather than applying them unasked. See user saikrishna hardware.

## tailscale-panel

_Standalone Tailscale Panel project (repo sxi9/tailscale-panel, private) deployed on the Ubuntu host at port 8090 as a systemd user service; Dropzone is public via Funnel on 8443_

Tailscale Panel: standalone Flask control panel for the Ubuntu host's Tailscale node (local clone D:\physical_ai\tailpanel, private GitHub repo https://github.com/sxi9/tailscale-panel, branch main). Deployed at `~/tailpanel` on saibala@192.168.29.22, running as a **user** systemd unit (`systemctl --user ... tailpanel`, linger is enabled, no sudo needed), port 8090, own accounts in `~/tailpanel/data/users.json` (`venv/bin/python app.py set-password admin`). Deploy = `git archive HEAD | ssh ... tar -x -C ~/tailpanel` then `systemctl --user restart tailpanel`. ufw is active on the host; 8090 is opened only for 192.168.29.0/24 and 100.64.0.0/10 (setup script `~/tailpanel-setup.sh`). saibala is the tailscale operator, so serve/funnel work without sudo.

As of 2026-10-13 Dropzone is PUBLIC via Funnel at https://leakwatch.tail765a4c.ts.net:8443 (drop-in `/etc/systemd/system/dropzone.service.d/tailscale.conf` sets DROPZONE_HTTPS=1 and DROPZONE_TRUST_PROXY=1). Port 443 Funnel belongs to the user's ~/leakwatch app (run.py, port 8787). Port 10000 Funnel = Bored Chat (Caddy 8080) since 2026-10-18; 8446 tailnet-only = whatsapp-headless 3001; 8447 tailnet-only = Dropzone screen bridge 6080. Funnel only reaches the internet on 443/8443/10000.

**Why:** the user wants one place to see what the Ubuntu box exposes and to toggle hosted services between tailnet-only and public.

**How to apply:** never publish the panel itself; test changes with the fake-tailscale shim approach (scratch test suite) before deploying. See dropzone server.
